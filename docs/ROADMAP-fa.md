# مسیر ادامه و معیار تکمیل

## اولویت صفر: پذیرش زیرساخت روی محیط واقعی

۱. SQL Server آزمایشی، migration، ساخت مدیر اولیه و ورود HTTPS.
۲. تعریف دو شعبه و یک کارمند؛ اثبات رد دسترسی به شعبه دیگر در پنل و API.
۳. تعریف غذا، چند تصویر، گروه، عرضه، افزودنی و ظرفیت امروز/فردا.
۴. آزمایش هم‌زمانی و unique constraint با دو connection واقعی SQL Server.
۵. ایجاد خطای کنترل‌شده و تأیید ErrorLogs؛ تأیید AuditLogs و rollback تراکنش.
۶. مرور موبایل/دسکتاپ، نصب PWA و cache آفلاین با مرورگر واقعی.

معیار تکمیل این گام: نتیجه هر مورد با دستور، محیط، تاریخ، SHA و محدودیت‌ها ثبت شود. تست InMemory جای آزمون تراکنش SQL نیست.

## اولویت یک: تکمیل کیفیت فاز مدیریت

ویرایش فرم با حفظ ورودی در خطاهای سرور، نمایش نام غذا به‌جای شناسه در بعضی dropdownها، ثبت مقدار قبل/بعد در Audit، مدیریت آپلود فایل با محدودیت نوع/اندازه، تعطیلی روز خاص، بازه/هم‌پوشانی ساعت‌ها و پاکسازی لاگ‌ها با سیاست نگهداری تأییدشده. یکسان‌سازی همه متن پیام‌ها در منبع مرکزی نیز هنوز کامل نشده است.

## اولویت دو: تحلیل سناریوی مشتری با مالک

نیازهای مشتری، OTP، آدرس و ارسال، سفارش، Snapshot قیمت و افزودنی‌ها، رزرو موقت و انقضا، فاکتور و پرداخت، لغو و بازپرداخت، قوانین باشگاه و گزارش فروش. قبل از این تحلیل endpoint پرداخت یا محاسبه سود/امتیاز واقعی اضافه نشود.

## قواعد اجرا

هر جلسه فقط دامنه تأییدشده را تغییر دهد؛ تغییر UI مرجع به‌عنوان طراحی جدید تلقی نشود. ابتدا وضعیت Git و AGENTS خوانده شود، سپس تست متناسب و مستندسازی انجام شود. وضعیت نامعلوم با برچسب نامعلوم بماند.
