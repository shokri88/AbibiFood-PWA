# نقطه شروع انتقال آبی‌بی — Frontend

## وضعیت این شروع

این مخزن `shokri88/AbibiFood-PWA` است. مخزن همراه: https://github.com/shokri88/AbibiFood-NetCore . مرجع طراحی: AbibiFood-UI در SHA `2af3cb18ef8c3de657fe2284db0209379fc2ee09`.

فرانت فعلی Angular با هشت Route آغازین است؛ قالب ۲۰ صفحه‌ای در `template-reference/` محفوظ است. انتقال کامل صفحات حساب/باشگاه هنوز انجام نشده. حالت پیش‌فرض template با برچسب نمونه است؛ mode=api کاتالوگ واقعی را می‌خواند و در شکست API به داده نمونه fallback نمی‌کند.

## افزودن مستقیم از کارت غذا — ۲۰۲۶-۱۰-۳۱

مبنای تغییر `9752313` است. در خانه، کاروزل تخفیف و منو، کارت مشترک FoodCard دکمه افزودن و کنترل تعداد دارد. لینک «اطلاعات تکمیلی» و تصویر/نام غذا همچنان صفحه مستقل محصول را باز می‌کنند؛ برای افزودن دیگر مجبور به ورود به آن صفحه نیستید.

اولین افزودن از کارت وقتی تعداد آن غذا در سبد صفر است: اگر افزودنی مجاز تعریف شده باشد، dialog بومی مرورگر باز می‌شود؛ در غیر این صورت مستقیم اضافه می‌شود. انتخاب افزودنی اختیاری است و هر افزودنی فعلاً یک واحد همراه هر غذاست. تأیید یک ردیف غذا با addonIds ثبت می‌کند؛ بستن/لغو چیزی اضافه نمی‌کند. افزودن بعدی آخرین ردیف ترکیب همان غذا را افزایش می‌دهد؛ کاهش از همان ردیف شروع می‌شود. عدد کارت مجموع تمام ترکیب‌های آن غذاست. با حذف آخرین واحد، افزودن دوباره انتخاب افزودنی را باز می‌کند. برای ترکیب متفاوت می‌توان از صفحه اطلاعات تکمیلی استفاده کرد.

قیمت تخفیفی در کارت و جمع پاپ‌آپ لحاظ می‌شود. آیتم دارای remaining=0 قابل افزودن نیست و افزودنی ناموجود غیرفعال است؛ این کنترل صرفاً UI است و رزرو/فروش قطعی نیست. سقف قبلی ۲۰ واحد در هر ترکیب حفظ شد؛ تغییر شعبه در زمان نمایش dialog مانع ثبت انتخاب قدیمی در سبد شعبه جدید می‌شود.

در حالت template دو رابطه نمونه افزوده شد: غذاهای ۱ و ۲ می‌توانند غذای ۳ (سیب‌زمینی) را همراه داشته باشند؛ این نمونه از همان مخزن غذاست. mode=api همچنان فقط رابطه‌ها و غذاهای پاسخ API را مصرف می‌کند؛ fallback یا endpoint جدید ساخته نشد. بک‌اند و قالب دست‌نخورده template-reference تغییر نکردند.

اعتبارسنجی: npm run build موفق؛ npm test -- --watch=false شامل ۱۳ تست موفق (۸ سرویس سبد، ۵ کامپوننت کارت)؛ diff check موفق. تست‌ها با JSDOM هستند و showModal/close شبیه‌سازی شده‌اند؛ تست بصری، فوکوس/ESC در مرورگر واقعی و پذیرش روی دستگاه هنوز انجام نشده است.

درخواست سبک‌ترشدن فونت فرانت هنوز کامل نشده: مخزن فقط چهار فایل ثابت Hasti Heavy با وزن CSS ۹۰۰ دارد؛ Regular/Medium موجود نیست. تغییر صوری font-weight وزن واقعی آن فایل را سبک نمی‌کند. فونت هستی و فایل‌های موجود حفظ شدند؛ برای تکمیل نیاز به فایل مجاز وزن سبک‌تر از مالک است.

## اصلاح مخزن غذا و نمایش تصاویر — ۲۰۲۶-۱۱-۰۳

CatalogService تمام تصاویر API را به ترتیب پاسخ حفظ می‌کند؛ تصویر اول همچنان تصویر کارت است و تصاویر بعدی به ترتیب در صفحه جزئیات غذا نمایش داده می‌شوند. بک‌اند تصاویر فعال را با SortOrder و سپس Id مرتب می‌کند؛ برای تصویر اصلی ترتیب ۰ و برای بقیه ۱ به بعد تنظیم شود. در نبود تصویر، لوگوی قبلی نمایش داده می‌شود. اگر ترتیب ۰ تعریف نشده باشد، اولین تصویر فعال مرتب‌شده تصویر اصلی جایگزین است. قالب مرجع و داده‌های آن تغییر نکردند.

اعتبارسنجی: Build production موفق؛ ۱۴ تست موفق شامل تست جدید حفظ ترتیب تصاویر، تصویر اصلی و حالت بدون تصویر. آزمون بصری مرورگر/دستگاه انجام نشده است.

## مبالغ صحیح و جداکننده هزارگان — ۲۰۲۶-۱۱-۰۳

قیمت، قیمت تخفیفی و مجموع مبالغ در کارت غذا، انتخاب افزودنی، جزئیات و سبد با DecimalPipe و قالب 1.0-0 نمایش داده می‌شوند: جداکننده هزارگان و بدون رقم اعشاری. محاسبات سبد و قرارداد داده تغییر نکرده‌اند. Build production و ۱۴ تست موفق؛ بررسی بصری مرورگر اجرا نشده است.

## اسپلش، تصاویر گروه، آیکن‌ها و پرفروش‌ها — ۲۰۲۶-۱۱-۰۳

قاب App در مسیر ریشه (حتی با query/hash) هدر و منوی پایین و container را حذف می‌کند؛ اسپلش با لوگوتایپ قالب مرجع تمام صفحه است و timer پس از خروج پاک می‌شود. کارت، جزئیات، سبد و بنر غذا قاب مربع و object-fit:contain دارند؛ بنر نیز از غذای دریافتی سرور تصویر می‌گیرد، نه تصاویر ثابت نمونه. تصاویر گروه از imagePath بک‌اند با آدرس API در خانه و منو نمایش داده می‌شوند. همه آیکن‌های متنی کنترلی برنامه با Font Awesome Free 6.7.2 محلی جایگزین شدند؛ مجوز در public/assets/vendor/fontawesome/LICENSE.txt است و فایل‌های media در تنظیمات cache سرویس‌ورکر پوشش داده می‌شوند. قالب مرجع تغییر نکرد.

پیش‌فرض config به mode=api با https://localhost:7043 مطابق آدرس کاربر تغییر کرد؛ فرانت کاربر http://localhost:4200 است. CORS بک‌اند از قبل همین origin را دارد؛ appsettings مالک تغییر نکرد. در استقرار واقعی آدرس API باید تنظیم و گواهی HTTPS معتبر/مورداعتماد باشد. fallback خودکار به داده نمونه وجود ندارد.

بخش پرفروش‌ترین‌ها از bestSellerIds پاسخ منو استفاده می‌کند؛ بک‌اند مجموع Sold ثبت‌شده تا امروز را برای غذای فعال و مستقل همان شعبه رتبه‌بندی می‌کند. ظرفیت، رزرو، ترتیب قالب و آینده معیار نیستند. در نبود فروش ثبت‌شده این بخش مخفی است؛ داده یا رتبه ساختگی تولید نمی‌شود. جدول سفارش/پرداخت و ثبت عملیاتی فروش هنوز وجود ندارد؛ این تغییر آن جریان را پیاده نمی‌کند.

اعتبارسنجی: Build production و ۱۵ تست فرانت موفق؛ Chromium واقعی روی عرض‌های ۳۶۰، ۳۹۰ و ۱۲۸۰، اسپلش بدون فاصله/ناوبری و بازگشت ناوبری، قاب مربع، آیکن‌های محلی، تصویر گروه و ترتیب/حالت خالی پرفروش‌ها را با پاسخ API کنترل‌شده بررسی کرد. اتصال به سرور دستگاه کاربر از این محیط آزموده نشده است.
